# ЛР2. Трекинг объекта на видео на основе ключевых точек

**Цель работы:** реализовать простейший алгоритм трекинга объекта на видео на основе ключевых точек.

Программа принимает видео, первым кадром которого является крупное изображение отслеживаемого
объекта. На каждом кадре, где объект виден, вокруг него рисуется рамка с подписью.

Язык реализации — Python, библиотеки — OpenCV и NumPy. Исходный код и результаты выложены в этом
репозитории.

---

## 1. Теоретическая база

### Ключевые точки и дескрипторы
Ключевые точки — характерные локальные фрагменты изображения (углы, края, пятна),
инвариантные к небольшим геометрическим и фотометрическим изменениям. Каждой точке
ставится в соответствие **дескриптор** — вектор, описывающий локальную окрестность точки.
Сравнение дескрипторов позволяет находить соответствия между изображениями (эталоном и кадром).

### ORB (Oriented FAST and Rotated BRIEF)
ORB сочетает детектор **FAST** и дескриптор **BRIEF** с добавлением ориентации и поворотной
инвариантности. Дескриптор BRIEF — бинарная строка, поэтому сравнение выполняется быстро по
метрике **Хэмминга**. Детектор строит **пирамиду масштабов** (в работе `nlevels=12`,
коэффициент `1.2` — покрытие до ~7× по масштабу), что обеспечивает частичную масштабную
инвариантность. ORB свободен для использования и работает в реальном времени.

### Сопоставление дескрипторов
Для поиска соответствий используется **BFMatcher** с метрикой **NORM_HAMMING**. Применяются два
взаимозаменяемых способа отсева ложных пар:
- **Взаимная проверка (crosscheck).** Пара принимается только если точка эталона — ближайший
  сосед для точки кадра *и* наоборот. Это сразу отсеивает большую часть ложных соответствий.
- **Ratio-тест Лоу.** Для каждой точки эталона находятся два ближайших соседа среди
  дескрипторов кадра. Сопоставление считается надёжным, если
  `d1 < ratio · d2` (в работе `ratio ≈ 0.85`). Это отсеивает неоднозначные соответствия.

### Гомография и RANSAC
Так как объект плоский, его положение на кадре описывается **гомографией** — проективным
преобразованием 3×3, переводящим точки эталона в точки кадра. Оценка гомографии по набору
сопоставлений выполняется методом **RANSAC**, который устойчив к выбросам: случайные
подмножества из 4 пар используются для построения гипотезы, а «правильная» гипотеза
выбирается по числу поддерживающих её точек (inlier'ов). Зная гомографию, углы эталона
проецируются в кадр — полученный четырёхугольник и есть рамка объекта.

## 2. Описание разработанной системы

### Архитектура
Проект состоит из следующих модулей:

| Файл | Назначение |
|------|-----------|
| `tracker.py` | Основной алгоритм трекинга (`KeypointTracker`) и CLI для обработки видео |
| `generate_test_videos.py` | Генерация синтетических тестовых видео (с known ground truth) |
| `evaluate.py` | Оценка точности трекинга (IoU с ground truth) на синтетических тестах |

`tracker.py` устроен слоями:
- **`KeypointTracker`** — класс, инкапсулирующий всё состояние (эталон, ORB, матчер, последняя
  рамка, состояние межкадрового трекинга). Обрабатывает один кадр.
- **`process_video()`** — функция верхнего уровня: открывает видео, берёт первый кадр как эталон,
  в цикле вызывает `tracker.track(frame)` и пишет результат.
- **`main()`** — CLI-обёртка (разбор аргументов, выбор выходного файла).

### Алгоритм трекинга (`tracker.py`)
1. **Инициализация.** Первый кадр видео принимается за крупное изображение объекта и
   становится **эталоном**. Для эталона вычисляются ключевые точки и дескрипторы ORB
   (`cv2.ORB_create(nfeatures=3000, scaleFactor=1.2, nlevels=12)`), запоминаются 4 угла эталона.
2. **Прямое сопоставление с эталоном.** Для каждого следующего кадра:
   - вычисляются ключевые точки и дескрипторы кадра (`orb.detectAndCompute`);
   - дескрипторы сопоставляются с эталоном (`cv2.BFMatcher`, метрика HAMMING);
   - ложные пары отсеиваются взаимной проверкой (по умолчанию) либо ratio-тестом Лоу;
   - по оставшимся парам оценивается гомография (`cv2.findHomography`, `RANSAC`, порог 5 px);
   - углы эталона проецируются через гомографию (`cv2.perspectiveTransform`) —
     полученный четырёхугольник является рамкой объекта;
   - рамка принимается, если число inlier'ов ≥ порога (`min_inliers=6`), а сама рамка проходит
     проверки геометрии и временной согласованности.
3. **Временная пропагация (`_propagate`).** Если прямое сопоставление не дало устойчивой рамки
   (объект мал или размыт), но в предыдущем кадре рамка уже построена, рамка переносится на
   текущий кадр: оценивается гомография «предыдущий → текущий» по точкам **внутри прошлой рамки**
   и компонуется `H(эталон→текущий) = H(пред→тек) @ H(эталон→пред)`.
4. **Проверки валидности рамки** (защита от ложных срабатываний):
   - `_box_valid` — геометрия: выпуклость, разумная площадь, невырожденные пропорции;
   - `_temporal_ok` / `_area_ok` — временная согласованность: размер не меняется более чем в 3 раза
     между кадрами, центр не «прыгает» дальше диагонали рамки.
5. **Отрисовка.** Зелёная рамка и подпись `object`; если объект не найден — красная подпись
   `object: not found`.

### Тестовые данные
Для проверки использованы **реальные видео** (без ручной разметки ground truth), каждое
согласовано с форматом алгоритма: первый кадр — крупное изображение отслеживаемого объекта.

| Видео | Разрешение | Кадров | Сценарий |
|-------|-----------:|-------:|----------|
| `mona-lisa.mp4` | 640×360 | 558 | Эталон — фрагмент картины «Мона Лиза»; в сцене фрагмент лежит на письменном столе среди посторонних предметов |
| `mona-lisa-blur.mp4` | 640×360 | 558 | Тот же сюжет с размытием — проверка устойчивости к дефокусировке |
| `mona-lisa-blur-extra-credit.mp4` | 640×360 | 558 | Усложнённый вариант с иным характером искажения (дополнительное задание) |
| `IMG_4951.mov` | 1080×1920 | 544 | Эталон — печатный документ-памятка (СМАД); в сцене лист лежит на тёмной фактурной поверхности; портретный кадр |

Вспомогательные скрипты `generate_test_videos.py` и `evaluate.py` позволяют дополнительно
сгенерировать синтетические тесты (поступательное движение, масштаб+вращение, уход из кадра,
«своё» видео) и измерить по ним **IoU** с известным ground truth.

## 3. Результаты работы и тестирования системы

### Метрики
Для реальных видео нет ручной разметки ground truth, поэтому оценка проводилась по двум
показателям, снимаемым самим алгоритмом:
- **доля кадров с найденным объектом** — процент кадров сцены, где алгоритм построил рамку;
- **среднее число inlier'ов** — мера уверенности сопоставлений (число точек, поддержавших
  гомографию после RANSAC).

| Видео | Кадров сцены | Найдено | Среднее число inlier'ов |
|-------|-------------:|--------:|------------------------:|
| `mona-lisa.mp4` | 557 | 517 (92.8%) | 144.9 |
| `mona-lisa-blur.mp4` | 557 | 420 (75.4%) | 87.8 |
| `mona-lisa-blur-extra-credit.mp4` | 557 | 518 (93.0%) | 115.8 |
| `IMG_4951.mov` | 543 | 472 (86.9%) | 94.1 |

### Анализ
- **Базовый сценарий** (`mona-lisa`) — 92.8% кадров, самое высокое среднее число inlier'ов (≈145):
  алгоритм уверенно отслеживает фрагмент картины в зашумлённой сцене с посторонними предметами;
  ложных срабатываний на фоне не наблюдается (работают проверки `_box_valid`/`_temporal_ok`).
- **Размытие снижает надёжность** (`mona-lisa-blur`, 75.4%): дефокусировка «размазывает» ключевые
  точки, число надёжных сопоставлений падает (≈88 inlier'ов против ≈145). Это ожидаемое ограничение
  детекторов ключевых точек.
- **Extra-credit вариант** (`mona-lisa-blur-extra-credit`, 93.0%) отследился лучше простого
  размытия — результат зависит от конкретного характера искажения.
- **Печатный документ** (`IMG_4951`, 86.9%): лист плотно текстурирован текстом, поэтому сопоставлений
  достаточно, однако на отдельных кадрах (сильный наклон, блик, частичный выход из кадра) объект
  теряется.
- В целом во всех сценариях потери носят фрагментарный характер и зачастую восстанавливаются за счёт
  временной пропагации рамки между соседними кадрами.

### Как запустить
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# трекинг одного видео: результат сохраняется рядом как *_tracked.mp4
python tracker.py videos/mona-lisa.mp4
python tracker.py videos/IMG_4951.mov

# дополнительно: генерация синтетических тестов и оценка IoU по ground truth
python generate_test_videos.py
python evaluate.py
```

## 4. Выводы по работе
1. Реализован работающий трекинг плоского текстурированного объекта на основе ключевых точек
   ORB, сопоставления дескрипторов по Хэммингу (взаимная проверка / ratio-тест Лоу) и оценки
   гомографии методом RANSAC, с временной пропагацией рамки и проверками её геометрии.
2. На реальных видео алгоритм уверенно отслеживает печатные и живописные объекты в сценах с
   посторонними предметами (доля найденных кадров ≥ 86% в базовых сценариях), не давая ложных
   срабатываний на фоне.
3. Основное ограничение — чувствительность к **размытию** (дефокусировка снижает число надёжных
   сопоставлений и долю найденных кадров) и требование **плоского текстурированного** объекта.
4. Для реальных видео без ground truth точность рамки (IoU) не измерялась; метрикой служила доля
   найденных кадров и число inlier'ов. Для количественной оценки точности рамки предусмотрена
   генерация синтетических тестов с известным ground truth (`evaluate.py`).
5. Для полной робастности (перекрытия, деформации, сильное размытие) целесообразно комбинировать
   подход с фильтрами состояния (например, KCF / MedianFlow из OpenCV) или пересопоставлением.
